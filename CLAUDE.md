# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Single-script NLP pipeline (`smartinfo.py`) that extracts keyword frequency indexes from Swiss drug information documents (Fachinfos). It reads HTML Fachinfos from an AmiKo SQLite database, tokenizes them with NLTK, filters/normalizes the words, and writes a keyword → registration-number index used for full-text search in the AmiKo apps.

## Running

```bash
python3 smartinfo.py --lang=de   # or --lang=fr
```

Dependencies (install into a venv): `nltk`, `bs4`, `lxml`. NLTK data must be downloaded once: `nltk.download('stopwords')`, `nltk.download('punkt')`, and on Python 3.13+ also `nltk.download('punkt_tab')`.

Prerequisite data: `dbs/amiko_db_full_idx_de.db` and `dbs/amiko_db_full_idx_fr.db`, generated by [cpp2sqlite](https://github.com/zdavatz/cpp2sqlite). In this checkout `dbs` is a symlink to `../cpp2sqlite/output/`. Both `dbs/` and `output/` are gitignored.

There are no tests and no linter.

A Rust port lives in `rust/` (`cargo build --release`, then run
`./rust/target/release/smartinfo --lang=de` from the repo root). It produces
byte-identical output to the Python script (~4× faster, ~half the memory) and
must be kept in sync when the pipeline changes; see `rust/README.md`.

## Pipeline architecture

Everything happens in `main()` in one pass over all rows of the `amikodb` table (column 1 = title, column 5 = Swissmedic registration number, column 15 = HTML content):

1. **HTML cleanup** (`remove_html_tags`): parses with BeautifulSoup/lxml and removes administrative sections that must not be indexed — title/owner divs, sections 17–21 and their C++-app equivalents (`Section7750`–`Section9051`). Subsections of section18 (`section180`, `section181`, …) hold drug-shortage info and are deliberately preserved while `section18` itself is dropped.
2. **Tokenization** (`get_tokens`): NLTK word tokenizer wrapped by an `MWETokenizer` so multi-word terms from `input/multiwords_<lang>.txt` become single tokens (underscore-joined, later restored to spaces). Filters stopwords, punctuation, integers, and words shorter than 3 chars.
3. **Normalization** (`clean_up_string`): a stack of regexes stripping special characters, number artifacts, time formats, etc. Words in `input/whitelist_<lang>.txt` are exempt from number-stripping and the minimum-length rule — the whitelist is the escape hatch when a legitimate term (e.g. `ACE-Hemmer`, `1B1`, E-numbers) gets mangled.
4. **Chapter mapping** (`find_chapters_with_tokens`): for each document, records which `section<N>` divs contain each token, so the index entry becomes `regnr(chapter1,chapter2,...)`.
5. **Output**: words occurring across more than 600 registrations (and not whitelisted/multiword) are diverted to `output/auto_stopwords_<lang>.csv`; everything else goes to `output/frequency_<lang>.csv` (`word;regnr(chapters)|regnr(chapters)|…`) and to `output/amiko_frequency_<lang>.db` (table `frequency`: truncated-SHA256 id, keyword, regnr string).

## Conventions

- Everything is per-language: input/output filenames and any language-specific logic are keyed by the `de`/`fr` dict pattern at the top of `main()`. New behavior should support both languages.
- Most maintenance is curating the `input/` word lists (stopwords, whitelist, multiwords), not code changes. When a valid medical term is being filtered or mangled, the fix is usually a whitelist entry — see git history and GitHub issues (#5, #15, #18) for precedent.
